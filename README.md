Proyecto: Análisis, Arquitectura de Datos y Modelado de Software (UML)

Este repositorio contiene el portafolio arquitectónico integral y la ingeniería de requerimientos desarrollados durante mi formación profesional como **Tecnólogo en Análisis y Desarrollo de Software**. El objetivo de este proyecto es demostrar mi dominio en el ciclo de vida del desarrollo de software (SDLC), el diseño de bases de datos relacionales, el modelado del comportamiento del sistema y la creación de documentación técnica estandarizada bajo lineamientos de la industria.

---

Stack Metodológico y Herramientas
* Lenguaje de Modelado: Unified Modeling Language (UML) para diseño de sistemas.
* Modelado de Datos: Estructuración de Bases de Datos Relacionales (SQL / MySQL).
* Gestión de Entornos: Organización estructurada de artefactos del software mediante control de versiones.
* **Diseño de Interfaz:** Prototipado y Mockups de experiencia de usuario (UX/UI).

---

Estructura del Portafolio y Artefactos

El portafolio se encuentra organizado de forma modular, abarcando las fases críticas de planificación, análisis y diseño técnico:

1. Ingeniería de Requerimientos y Documentación
* DOCUMENTO ANALISIS: Especificación de Requerimientos de Software (SRS) que define el alcance, las reglas de negocio y los casos de uso del sistema.
* DOCUMENTO GTI: Gestión Tecnológica Institucional y lineamientos metodológicos del proyecto.
* Formatos primer trimestre`: Plantillas estandarizadas para el control y seguimiento del ciclo de vida del desarrollo.

2. Diseño de Arquitectura y Comportamiento del Sistema (UML)
* DIAGRAMA DE CLASES: Estructura estática del software, definiendo objetos, atributos, métodos y sus relaciones de herencia o asociación.
* Diagrama de componentes: Organización y dependencias entre los módulos de código y piezas de software independientes.
* Diagramas de secuencia: Modelado dinámico que describe la interacción cronológica de los objetos ante un flujo o escenario específico.
* Diagrama de despliegue: Arquitectura de infraestructura física, mostrando cómo se distribuyen los artefactos en los nodos de ejecución (servidores, clientes).
* Diagrama de paquetes: Organización lógica del sistema para mantener un código limpio y modularizado.
* DIAGRAMA DE ESTADOS / Diagrama de comunicacion: Representación detallada de los ciclos de vida de las entidades y las vías de comunicación de los procesos.

3. Ingeniería y Arquitectura de Datos
* DIAGRAMA ENTIDAD RELACION (DER): Conceptualización gráfica de las entidades del negocio y sus respectivas cardinalidades.
* MODELO RELACIONAL: Mapa de bases de datos relacionales, detallando restricciones de integridad, llaves primarias (`PK`) y llaves foráneas (`FK`).
* DICCIONARIO DE DATOS: Documentación técnica exhaustiva que define el tipo de dato, restricciones, obligatoriedad y descripción de cada campo del sistema para garantizar la gobernanza de datos.

4. Infraestructura y Prototipado
* Diagrama de Red: Arquitectura de conectividad, topología y flujos de red requeridos por el software.
* MOCKUP: Prototipos de interfaces gráficas orientados a optimizar los flujos de navegación y la usabilidad (UX) antes de la fase de codificación.
